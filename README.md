# Worms Armageddon на Orange Pi Zero 3W

Запуск Worms Armageddon (1999, сборка GOG и/или русский репак) на Orange Pi Zero 3W
под **Hangover** — Wine, собранный под arm64. Игра идёт без эмуляции всей установки
через box64, играется в окне 1024×600, отдельный профиль Wine не мешает другим играм
(например Disciples II).

**Проверено на:** Orange Pi Zero 3W (Allwinner A733), Debian 13 (trixie), рабочий стол
MATE/X11, экран 1024×600 по HDMI, Hangover `hangover-wine 11.16` + `box64 0.3.4`,
ядро `6.6.98-sun60iw2`.

**Быстрый путь — [INSTALL.md](INSTALL.md):** пошаговые блоки для копирования в терминал
плюс полный код всех скриптов (установка возможна даже без `git clone`).

## Что нужно от вас

- плата или другая arm64-машина под Debian 13 с рабочим X11-столом;
- **своя копия игры**: чистая GOG-сборка (распаковывается без установщика) или
  установщик/репак Inno Setup. Файлов игры в репозитории нет — только порядок действий
  и скрипты;
- ~3,5 ГБ на диске: Hangover ~2,3 ГБ, профиль Wine с игрой ~2,8 ГБ (из них игра 542 МБ).

## Порядок в двух словах

```bash
bash scripts/01-install-hangover.sh              # Wine для arm64 (один раз на систему)
bash scripts/worms-setup-prefix.sh               # чистый профиль Wine (~ до 20 мин)
#   → скопировать файлы игры в ~/.wine-worms-hg/drive_c/Worms
bash scripts/worms-zero.sh                       # играть
```

Русский репак ставится отдельно, в тот же профиль: `bash scripts/worms-ru-install.sh`
(каталог репака задаётся переменной `REPACK`).

## Экран: только через меню самой игры

- Игра знает **только 4:3**: 640×480, 800×600, 1024×768. Режим 1024×600 принимается
  исключительно как **оконный** и только через меню ОПЦИИ игры — правки реестра она
  игнорирует (падает на 640×480).
- При переборе режимов **X может «залипнуть»** (чёрный экран, кривое разрешение) — лечится
  перезапуском графического сеанса, поэтому перебирать режимы лучше не подряд.
- Лончер после выхода сам возвращает режим экрана (`xrandr --output <выход> --mode 1024x600`).
- Софтверный рендер (`HardwareRendering=0` в реестре профиля) для этой игры и есть рабочий
  вариант: игра не берёт GPU-контекст, идёт через Xorg, загрузка CPU ~180 %, температура ~58 °C.

## Курсор и джойстик

В игре курсор ведёт сама игра, а указатель у системы перехватывает и центрует. Если стик
двигает курсор рывками или «доигрывает» прошлые движения — это лечится игровым режимом
драйвера `m5hub` и сторожем игрового курсора. Подробно, с числами и диагностикой:
**[docs/cursor-and-stick.md](docs/cursor-and-stick.md)**.

Коротко: сторож ставит пометку `/tmp/m5hub-direct`, и в игре драйвер переходит на
относительный ход, без медианного фильтра, со скоростью по времени (40–330 пикс/с).

## Грабли (все пройдены лично)

1. **`could not load kernel32.dll` при первом запуске** — профиль Wine создан
   недоинициализированным (`wineboot` убили по таймауту). Лечится `scripts/worms-setup-prefix.sh`:
   файлы игры откладываются, профиль создаётся заново, файлы возвращаются.
2. **Видеорежим X залипает** после серии переключений режима — перезапуск графического сеанса;
   режим менять только в меню игры и по одному.
3. **Заставка ждёт нажатия клавиши** — лончер сам находит окно, активирует его и жмёт пробел.
4. **Звук**: в игре выставлена громкость около 25 % — так и оставить (громче не поднимать,
   выбрано на слух пользователя).
5. **Второй запуск не поднимается**, если остались процессы прошлого — лончер гасит
   `wineserver` и `WA.exe` перед стартом.

## Откат

Системных изменений скрипты не делают. Удалить:

```bash
rm -rf ~/.wine-worms-hg ~/worms-app-save ~/worms-zero.sh
# Hangover, если больше не нужен:
sudo apt-get remove hangover-wine hangover-wowbox64 hangover-libwow64fex hangover-libarm64ecfex
```
