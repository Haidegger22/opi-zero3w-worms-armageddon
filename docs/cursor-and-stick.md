# Курсор и джойстик в Worms Armageddon на Zero 3W

Здесь собрано всё, что выяснено измерением при настройке управления в игре:
почему курсор «живёт своей жизнью», откуда берутся «догонялки» и как подстроить
скорость под себя. Всё это делается двумя службами: **m5hub** (джойстик → указатель)
и **сторожем игрового курсора** (`game-cursor.py`).

Связанные репозитории:

- [`Haidegger22/opi-zero3w-m5hub`](https://github.com/Haidegger22/opi-zero3w-m5hub) — драйвер
  M5Stack-юнитов (джойстик, скролл, CardKB), в нём игровой режим стика;
- [`Haidegger22/opi-zero3w-cursor-comet`](https://github.com/Haidegger22/opi-zero3w-cursor-comet) —
  курсор-комета, пустой системный курсор и сторож игрового курсора.

## 1. Игра ведёт курсор сама

Worms Armageddon — игра 1999 года, курсор она рисует и ведёт сама, а указатель у системы
**перехватывает и центрует**: проверено `xdotool mousemove` — указатель не сдвигается,
остаётся в центре окна (512,300 при экране 1024×600).

Отсюда первый симптом — **два курсора**: наш оверлей-комета честно висит на указателе (в центре),
а курсор игры в это время ездит по экрану. Со стороны это «курсор есть, но живёт своей жизнью».

**Лечение:** сторож `game-cursor.py` знает класс окна игры (`wa.exe`) и в этом режиме
выключает комету, свой оверлей-прицел и мост клавиш — остаётся только курсор самой игры.
Проверка в журнале:

```bash
journalctl --user -u game-cursor -n 20 --no-pager
# ожидается: ИГРА ('wa.exe', 'wa.exe') — курсор ведёт игра, комета убрана
```

## 2. Четыре причины «догонялок» и рывков

Все четыре найдены не на глаз, а по считыванию координат стика
(см. раздел «Диагностика» ниже).

| Что было | Что происходило | Как исправлено |
|---|---|---|
| Медианный фильтр стика, окно 6 отсчётов (≈180 мс) | после смены направления указатель ещё едет по-старому | в игре фильтр выключен, работают сырые значения стика |
| Абсолютный перенос указателя | игра центрует указатель, и абсолютный перенос она читает как прыжок «от центра до нашей точки» | в игре ход **относительный**: от текущей позиции прибавляем ровно шаг |
| Шаг 110 пикс за такт (≈3500 пикс/с) | прыжки по сто пикселей: «очень резко», попасть в цель нельзя | шаг по кривой отклика: 2–16 пикселей, дробление на подшаги |
| Фактический такт 85 мс вместо 30 | скорость зависела от торможений цикла (чтение клавиатуры) и падала до ~188 пикс/с | скорость считается от времени: `шаг = скорость × dt` |

Итоговые настройки в игре: **40 пикс/с** на слабом наклонении стика (точное наведение)
и **330 пикс/с** на полном отклонении (экран проходится примерно за 3 с).

## 3. Как подстроить скорость

Правки — в `~/m5hub/m5hub.py`, в `Hub.__init__`. На рабочий стол они не влияют:
игровой режим включается только пометкой `/tmp/m5hub-direct`.

```python
self.GAME_SPEED_MIN = 40.0    # пикс/с при слабом наклонении (точность)
self.GAME_SPEED_MAX = 330.0   # пикс/с при полном отклонении (быстрота)
self.GAME_CURVE     = 1.5     # кривая: больше — точнее у центра, резче на полном ходу
self.GAME_SUB       = 3       # на сколько подшагов дробить шаг
self.GAME_SUB_SLEEP = 0.004   # пауза между подшагами, с
```

После правки:

```bash
python3 -m py_compile ~/m5hub/m5hub.py
sudo systemctl restart m5hub
[ -f /tmp/m5hub-direct ] && echo "игровой режим включён"   # при запущенной игре
```

| Симптом | Что менять |
|---|---|
| Медленно | поднять `GAME_SPEED_MAX` (400–500) |
| Резко на полном наклоне | опустить `GAME_SPEED_MAX` |
| Не хватает точности у центра | поднять `GAME_CURVE` (1.8–2.2) |
| Движение «ступеньками» | увеличить `GAME_SUB` до 4–5 |

## 4. Диагностика: считывание координат стика

Включается файлом-пометкой, пишет журнал по строке на такт:

```bash
touch /tmp/m5hub-joylog          # включить
tail -f /tmp/m5hub-joylog.txt    # смотреть живьём
rm /tmp/m5hub-joylog             # выключить
```

Формат строки:

```
1791236726.386 чтение=12 прочее=15 такт=26 мс | dx=-32664 dy=-7400 mag=33492 \
sdx=-33488 sdy=0 dir=2 sx=-112 sy=0 vx=7 vy=599 реал=512,300
```

| Поле | Что означает |
|---|---|
| `dx dy mag` | сырые оси стика и магнитуда (полное отклонение ≈ 32768) |
| `sdx sdy dir` | после фильтра и snap: значения и номер направления |
| `sx sy` | шаг указателя за этот такт, пиксели |
| `vx vy` | виртуальная позиция драйвера (куда он поставил указатель) |
| `реал=X,Y` | где указатель на самом деле в начале такта |
| `чтение/прочее/такт` | время на чтение стика, на остальное и такт целиком, мс |

На что смотреть:

- **`реал` не совпадает с `vx/vy` прошлого такта** → указатель двигает кто-то ещё (в игре —
  сама игра, она его центрует). Значит абсолютный ход для этой игры не годится.
- **`такт` сильно больше 30 мс** → цикл драйвера тормозит (у нас видели 85 мс из-за чтения
  клавиатуры); при шаге «на такт» это прямо снижает скорость.
- **`шаг` десятками-сотнями пикселей** → движение будет рывками, надо уменьшать.

Считывание выключать после разбора: файл растёт примерно 12 строк/с.

## 5. Быстрая проверка, что всё на месте

```bash
# 1) драйвер и игровой режим
systemctl is-active m5hub
[ -f /tmp/m5hub-direct ] && echo "прямой ход (игровой режим) включён"

# 2) сторож курсора и его решение по игре
systemctl --user is-active game-cursor
xwininfo -root -children | grep -i worms          # окно игры: класс wa.exe
xwininfo -root -children | grep -ci cursor-comet  # ожидается 0 — комета снята

# 3) обратимость: свернуть игру — комета должна вернуться
W=$(xdotool search --name 'Worms Armageddon' | tail -1)
xdotool windowunmap "$W"; sleep 5
xwininfo -root -children | grep -ci cursor-comet  # 2 — комета вернулась
xdotool windowmap "$W"
```

## 6. Что НЕ делать

- **Не двигать указатель синтетически** (`xdotool mousemove`, `warp`) при работающем m5hub:
  драйвер хранит свою позицию курсора и вернёт указатель на неё, а игра к этому моменту
  уже центрует его по-своему — получаете скачки. Если всё же двигали — перезапустите драйвер:
  `sudo systemctl restart m5hub`.
- **Не включать сглаживание обратно** «для плавности»: в этой игре оно читается как
  «курсор доигрывает прошлые движения».
- **Не править общий код драйвера ради игры**: все игровые настройки — только через
  `GAME_*` и пометку `/tmp/m5hub-direct`.
